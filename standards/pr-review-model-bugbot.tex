\section{Purpose and scope}

This machine checks the Bugbot conjuncts of $merge\_gate$. No reachable state
merges with a live run that has no ``proceed'' ruling. On a PR that is not
skipped, a merge never skips the re-run of a failed run of any round, and a
merge on the 30-minute fallback never comes before a full window after the
current round's re-run. Every non-merged
state can still move, and where none of this machine's own events can, the
Bugbot conjuncts of $merge\_gate$ hold (the deadlock lemma, I6).

\section{Given sets and enumerations}

\begin{zed}
  [RUN]
\end{zed}

\begin{zed}
  Flag ::= yes | no
\end{zed}

A run is live (queued or in progress) or done. A done run either finished its
review ($doneOk$: success or neutral) or reviewed nothing ($doneFail$: failure,
timeout, cancelled).

\begin{zed}
  RunStatus ::= live | doneOk | doneFail
\end{zed}

\begin{zed}
  ROUND == 1 \upto 3
\end{zed}

\section{State}

$runs$ gives each run its status, $runRound$ the round whose trigger started
it. $stuck$ marks runs live for over 60 minutes; $proceed$ marks runs the
operator ruled ``proceed''. $escRun$ holds escalated runs awaiting a ruling,
$escRunEver$ every run ever escalated (once per run, ever), and $waitRuled$ the
escalated runs ruled ``wait''. $retried$ is the rounds with a $rerun(N)$
comment; $timedOut$ the rounds whose 30-minute window has elapsed since the
trigger or the re-run. Two ghosts, read by no guard: $rerunAfterFail$ records
a re-run posted because a run of that round failed; $windowSinceRetry$
records that a full window elapsed after that re-run.

\begin{schema}{State}
  round : ROUND \\
  skipped, merged : Flag \\
  runs : RUN \pfun RunStatus \\
  runRound : RUN \pfun ROUND \\
  stuck, proceed, escRun, escRunEver, waitRuled : \power RUN \\
  retried, timedOut, rerunAfterFail, windowSinceRetry : \power ROUND
\where
  \dom runRound = \dom runs \\
  stuck \subseteq \dom runs \\
  proceed \subseteq stuck \\
  escRunEver \subseteq stuck \\
  waitRuled \subseteq escRunEver \\
  escRun \subseteq escRunEver \setminus waitRuled
\end{schema}

\section{Derived terms}

$bugbot\_in(N)$: a run of round $N$ finished its review; or the window
elapsed, no run is open, and every failed run of round $N$ has had its
$rerun(N)$.

\begin{schema}{BugbotIn}
  State
\where
  ( \exists r : \dom runs @ runRound~r = round \land runs~r = doneOk ) \lor \\
  ( round \in timedOut \land \\
  \quad~ ( \forall r : \dom runs @ runs~r = live \implies r \in proceed ) \land \\
  \quad~ ( ( \exists r : \dom runs @ runRound~r = round \land runs~r = doneFail ) \\
  \quad~\quad~ \implies round \in retried ) )
\end{schema}

$bugbot\_clear$: no live run without a ``proceed'' ruling, no open run
escalation, and every failed run's round has had its $rerun(N)$, whichever
round that is. A round-1 run can fail after round 2 opens.

\begin{schema}{BugbotClear}
  State
\where
  ( \forall r : \dom runs @ runs~r = live \implies r \in proceed ) \\
  escRun = \emptyset \\
  ( \forall r : \dom runs @ runs~r = doneFail \implies runRound~r \in retried )
\end{schema}

$Quiescent$: the PR is not merged and every event of this machine except
$BugbotStart$ is disabled. Each line is the negated precondition of one
event, in order: $BugbotEnd$, $BugbotStuck$, $EscalateStuck$, $Timeout$,
$RequestRetry$, $OperatorProceed$, $OperatorWait$; a change to one of those
guards changes its line here. $OpenRound2$ and $Merge$ are not this machine's
own events; they stand for the review side (B4).

\begin{schema}{Quiescent}
  State
\where
  merged = no \\
  \lnot ( \exists r : \dom runs @ runs~r = live ) \\
  \lnot ( \exists r : \dom runs @ runs~r = live \land r \notin stuck ) \\
  \lnot ( \exists r : stuck @ runs~r = live \land r \notin proceed \cup escRunEver ) \\
  round \in timedOut \\
  \lnot ( \exists r : \dom runs @ runs~r = doneFail \land runRound~r \notin retried ) \\
  escRun \cup waitRuled = \emptyset \\
  escRun = \emptyset
\end{schema}

\textbf{The deadlock lemma.} In every $Quiescent$ state the Bugbot conjuncts
of $merge\_gate$ hold: $BugbotClear$, and $BugbotIn$ unless the PR is skipped.
By cases.
\begin{itemize}
\item $BugbotClear$ false: either a live run without a ``proceed'' ruling
  exists, and then $BugbotEnd$ is enabled on it; or $escRun \neq \emptyset$,
  and then $OperatorProceed$ and $OperatorWait$ are enabled on its member; or
  a failed run's round $n$ has no $rerun(n)$, and then $RequestRetry$ is
  enabled for $n$. Each contradicts $Quiescent$. So no run is live,
  $escRun = \emptyset$, and every failed run's round is in $retried$.
\item $skipped = no$ and $BugbotIn$ false, with $round \notin timedOut$:
  $Timeout$ is enabled. A contradiction.
\item $skipped = no$ and $BugbotIn$ false, with $round \in timedOut$: no run
  is live and every failed run's round is in $retried$ (first case), so both
  remaining clauses of $BugbotIn$ hold. A contradiction.
\end{itemize}
The proof does not use $BugbotStart$, so the lemma holds even while a fresh
run could still start. Machine A uses it in ``Why the split is sound''.
ProB checks it as I6 below.

\textbf{The invariant.}
(I1, Bugbot half) A merge leaves no live run without a ``proceed'' ruling.
(I4) On a PR that is not skipped, a merge never skips the re-run of a failed
run of any round, and a merge on the fallback never comes before a full
window after the current round's re-run.
(I6) The deadlock lemma.

\begin{schema}{Invariant}
  State
\where
  merged = yes \implies ( \forall r : \dom runs @ runs~r = live \implies r \in proceed ) \\
  ( merged = yes \land skipped = no ) \implies \\
  \quad~ ( ( \forall r : \dom runs @ runs~r = doneFail \implies runRound~r \in rerunAfterFail ) \land \\
  \quad~\quad~ ( ( \exists r : \dom runs @ runRound~r = round \land runs~r = doneOk ) \lor \\
  \quad~\quad~\quad~ ( round \in retried \implies round \in windowSinceRetry ) ) ) \\
  Quiescent \implies ( ( skipped = yes \lor BugbotIn ) \land BugbotClear )
\end{schema}

\section{Runs}

A run starts, for the current round. A skipped PR may still get one, and
$bugbot\_clear$ still reads it.

\begin{schema}{BugbotStart}
  \Delta State \\
  r? : RUN
\where
  merged = no \\
  r? \notin \dom runs \\
  runs' = runs \cup \{ r? \mapsto live \} \\
  runRound' = runRound \cup \{ r? \mapsto round \} \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  proceed' = proceed \\
  escRun' = escRun \\
  escRunEver' = escRunEver \\
  waitRuled' = waitRuled \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}

A live run ends.

\begin{schema}{BugbotEnd}
  \Delta State \\
  r? : RUN \\
  s? : RunStatus
\where
  merged = no \\
  r? \in \dom runs \\
  runs~r? = live \\
  s? \in \{ doneOk, doneFail \} \\
  runs' = runs \oplus \{ r? \mapsto s? \} \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  proceed' = proceed \\
  escRun' = escRun \\
  escRunEver' = escRunEver \\
  waitRuled' = waitRuled \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}

A live run passes 60 minutes.

\begin{schema}{BugbotStuck}
  \Delta State \\
  r? : RUN
\where
  merged = no \\
  r? \in \dom runs \\
  runs~r? = live \\
  r? \notin stuck \\
  stuck' = stuck \cup \{ r? \} \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  proceed' = proceed \\
  escRun' = escRun \\
  escRunEver' = escRunEver \\
  waitRuled' = waitRuled \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}

The 30-minute window for the current round elapses, measured from the trigger
or from $rerun(N)$, whichever is later.

\begin{schema}{Timeout}
  \Delta State
\where
  merged = no \\
  round \notin timedOut \\
  timedOut' = timedOut \cup \{ round \} \\
  windowSinceRetry' = windowSinceRetry \cup \{ round \} \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  proceed' = proceed \\
  escRun' = escRun \\
  escRunEver' = escRunEver \\
  waitRuled' = waitRuled \\
  retried' = retried \\
  rerunAfterFail' = rerunAfterFail
\end{schema}

$rerun(N)$: the leader comments ``bugbot run'' once per round when a run of
that round reviewed nothing. The round-2 trigger is not a $rerun$, so
$OpenRound2$ leaves $retried$ alone. The guard does not read $bugbot\_in$: the
window may already have elapsed (defect (2)). Nor is it limited to the current
round: a round-1 run that fails after round 2 opens still gets $rerun(1)$.
The comment restarts round $n?$'s window.

\begin{schema}{RequestRetry}
  \Delta State \\
  n? : ROUND
\where
  merged = no \\
  ( \exists r : \dom runs @ runRound~r = n? \land runs~r = doneFail ) \\
  n? \notin retried \\
  retried' = retried \cup \{ n? \} \\
  rerunAfterFail' = rerunAfterFail \cup \{ n? \} \\
  timedOut' = timedOut \setminus \{ n? \} \\
  windowSinceRetry' = windowSinceRetry \setminus \{ n? \} \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  proceed' = proceed \\
  escRun' = escRun \\
  escRunEver' = escRunEver \\
  waitRuled' = waitRuled
\end{schema}

\section{Escalations and rulings}

The leader escalates a stuck run once per run, ever.

\begin{schema}{EscalateStuck}
  \Delta State \\
  r? : RUN
\where
  merged = no \\
  r? \in stuck \\
  runs~r? = live \\
  r? \notin proceed \cup escRunEver \\
  escRun' = escRun \cup \{ r? \} \\
  escRunEver' = escRunEver \cup \{ r? \} \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  proceed' = proceed \\
  waitRuled' = waitRuled \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}

The operator rules ``proceed'' on an escalated run, or later on a run already
ruled ``wait'', with no new escalation: the run no longer holds the gate.

\begin{schema}{OperatorProceed}
  \Delta State \\
  r? : RUN
\where
  merged = no \\
  r? \in escRun \cup waitRuled \\
  proceed' = proceed \cup \{ r? \} \\
  escRun' = escRun \setminus \{ r? \} \\
  waitRuled' = waitRuled \setminus \{ r? \} \\
  escRunEver' = escRunEver \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}

The operator rules ``wait'': the escalation closes, and the run holds the gate
until it ends or the operator rules ``proceed''.

\begin{schema}{OperatorWait}
  \Delta State \\
  r? : RUN
\where
  merged = no \\
  r? \in escRun \\
  escRun' = escRun \setminus \{ r? \} \\
  waitRuled' = waitRuled \cup \{ r? \} \\
  proceed' = proceed \\
  escRunEver' = escRunEver \\
  runs' = runs \\
  runRound' = runRound \\
  round' = round \\
  skipped' = skipped \\
  merged' = merged \\
  stuck' = stuck \\
  retried' = retried \\
  timedOut' = timedOut \\
  rerunAfterFail' = rerunAfterFail \\
  windowSinceRetry' = windowSinceRetry
\end{schema}
