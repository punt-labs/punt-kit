# Vox: OpenCode P1 and pi P2 implementation plan

**Priority update — 2026-09-13:** OpenCode is P1; pi is P2. Codex designs and task rows below are deferred research, including workers and controlled voice backends. They impose no active dependency or release gate. Research/source and Beads observations remain dated 2026-09-12. See [the scope decision](../decisions.md) and the [active roadmap](../roadmap.md).

## Baseline and actual architecture

Inspected `main`, `db1a4a9000fd1270d811e3b85f9aa67e8bcbde43`, package `punt-vox 5.0.5`. Initial and final status contain only unrelated ethos mission records; no Vox product source was changed by this audit. Repo-scoped inventory contains 380 beads. The report is source/design/test inspection, not a claim that live audio or harness integration tests were run.

Vox already has a substantial harness-independent engine and public clients. Keep and improve those boundaries; adding three adapter copies of today's MCP session logic would preserve the main defect.

## Mandatory product remediation

**VOX-STATE: make voxd authoritative for client session state.** `SessionConfig` in `server.py:135` generates a random session ID and stores notify/speak/voice/provider/model/vibe in a module singleton. `refresh_from_config` merges repo-global files back into it, and `notify`/`speak` write the shared files so hooks can observe changes. `ConfigStore` separates durable and ephemeral fields, but the ephemeral file is still one `vox.local.md` per repo, not one state per harness session. This is the exact open `vox-zugu` incident class. Move the session preference service and domain operations into voxd, keyed by explicit harness/native-session/agent/repo-worktree context. Keep repo preferences as defaults with deliberate “save default” semantics; do not infer CWD from PIDs or run `lsof` in the daemon. Make hook, CLI, MCP, panel and TS clients disposable projections. Preserve global music/program semantics where the current product intentionally shares them; session-keying does not mean cloning shared catalogs or audio hardware. [State singleton and refresh](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/server.py#L297), [disk writes](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/server.py#L607), [config ownership](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/config.py#L147).

The existing `vox-zugu` notes also carry an **already ratified, unimplemented provider/model design** from `vox-otj9`: make provider/model one engine-owned value object. `with_provider` returns a new pair using that provider’s default; `with_model` validates against that provider once. Replace the three independent cascade sites (`server_switches._commit_provider`, `panel/service._commit_provider`, `mic:provider`) with this invariant. `ProviderModels.default()` returns a Model, using `NullModel` for modelless providers, so callers no longer propagate `str | None` or test empty model lists. Design this together with state relocation; a native adapter must never hold or submit a half-updated pair. This is owed design work, not a new choice to seek approval for. Evidence is the full repo-scoped `vox-zugu` notes in the saved inventory; the narrower closed `vox-otj9` fix does not supersede them.

**VOX-CONTRACT: extract neutral control/event operations and publish their wire contract.** `unmute` is intentionally the agent speech operation while `vox say` is the direct-user CLI speech operation; preserve intent, not only names. Move validation, preference resolution and domain results out of MCP handlers into the session/control service; expose typed requests/results to every adapter. Add protocol version/capability information, request correlation, structured errors, cancellation/stop semantics and runtime/core version reporting. Reconcile the long client modules and `vox-165w` while doing this, rather than copying method drift into TS. A service unavailable or provider unavailable result must remain distinguishable from silent success. Existing audio-host behavior from closed `vox-dvri`/`vox-ovb7` is a prerequisite, not a task to reimplement.

**VOX-EVENTS (implemented within VOX-CONTRACT): accept native events, not Claude hook envelopes.** `handle_stop` returns `{"decision":"block"}` to provoke Claude's summary and speech; this is not an engine “turn completed” API. Design a small neutral event contract for session entered/left, user waiting, work completed, compaction and optional continuous signals. Engine preferences decide chime/speech policy and duplicate suppression; adapters obtain the recap using each host's supported context APIs. Keep agent-authored vibe decisions from DES-043. The recap quality decision named in `vox-o718` remains a real design choice; do not secretly replace it with a poor deterministic summary. Deduplicate completed-turn events and cap recap-triggered continuation to prevent loops. [Stop behavior](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/hooks.py#L225), [DES-043](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/DESIGN.md#L1950).

**VOX-ENABLE: separate activation from Claude registration.** The neutral `.punt-labs/vox/enabled` marker exists and should remain the sole repository gate. `RepoEnablement.enable()` currently deposits Claude guidance/import/settings before its marker. Split neutral repo enablement, selected harness registration and guidance projection while preserving marker-last crash safety and audible defaults. No automatic enabling of every detected harness. [Enablement order](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/enablement.py#L393). This explicitly amends two assumptions in `vox-o718`: preserving config ownership unchanged and auto-detecting/depositing OpenCode on enable conflict with this plan and the user's broad debt-remediation scope.

**VOX-CALL: reconcile conversation design before expanding it.** Source still uses per-turn `ClaudeSessionAttach` plus `claude agents --json` discovery; it is not an implemented native pi/OpenCode/Codex call layer. DES-065 rejects its latency; DES-066/067 describe a persistent pi call agent; later DES-068/069 propose ElevenLabs conversational E+ and DES-073 ratifies per-agent steering. Do not treat open `vox-hobl.2` as settled current architecture merely because earlier mechanism experiments were ratified. Reconcile the proposed E+ branch, existing conversation epic and recorded decisions into one execution plan. This does not block ordinary chimes/synthesis/recordings, but it is mandatory for calling a voice conversation feature first-class on a harness. [Actual attachment](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/voxd/conversation_mode/claude_session_attach.py#L79), [actual discovery](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/voxd/conversation_mode/session_discovery.py#L55), [E+ status](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/DESIGN.md#L3503), [ratified steering](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/DESIGN.md#L3754).

For all implementations, session identity is attribution, not an authorization grant. Microphone use, captured context, generated media costs, session launching and relayed user speech must follow the actual enabled/user-authorized operation. WS presently rejects browser Origin and validates a token; a new client must preserve that policy, not weaken it to ease a JS implementation. No tokens in URLs/logs beyond the existing explicitly controlled WS handshake; consider a versioned authenticated handshake/header evolution during the contract work, with redaction and compatibility tests. [Router admission](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/src/punt_vox/voxd/router.py#L60).

## Native integrations and deferred Codex research

**Codex (deferred).** Publish a native Codex plugin with MCP configuration, skills and native command hooks against the researched 0.154.0 baseline. Reuse the refactored MCP adapter for model operations; map Codex SessionStart/Stop/PermissionRequest/Interrupt/PreCompact/PostCompact and subagent events from actual Codex fixtures. A Codex Stop can request continuation, but do not run Claude scripts or assume Claude output fields. Bound recap work and send audio to the explicit voxd host. Product-state ownership is release-blocked on the shared Codex per-call context-binding spike: a hook cannot be assumed to export session identity into its parent or MCP child. For voice-first sessions owned by Vox, Codex App Server is a separate hosting lane with a native input/interrupt witness; it is not proof that a stock Codex plugin can inject arbitrary idle turns. Arbitrary TUI audio widgets are not established; use native skills/tools plus Vox/Lux presentation.

**OpenCode.** Reuse/amend `vox-o718` as the native program. Publish one versioned npm adapter with server and optional TUI exports. Server tools receive explicit `sessionID/agent/directory/worktree`, call voxd and serialize their own async event work. Translate `session.idle/status/error/compacted`, permission notifications and native text/tool events into the neutral event contract, reconciling resume and first-seen sessions. `permission.ask` is declared but not invoked by the audited engine; use native permission rules and tool `ctx.ask`/actual execution boundaries as appropriate, not that unused hook. TUI adds deterministic controls, voice status and local attention, with `lifecycle.signal`/`onDispose`; it must not redefine the configured audio host when attached to a remote server. Use current `@opencode-ai/plugin/tui` APIs pinned to 1.18.30 and test 1.18.27 separately. Voice steering uses supported session SDK APIs with receipts and user words, not tmux injection.

**Pi.** Ship a native pi package containing TS `registerTool`/`registerCommand`, workflow skills, and keyed status UI. Use direct WS for low-latency media/control and finite JSON CLI calls where suitable; **no MCP bridge**, per DES-067. Build the connection on session_start/first use, close on session_shutdown, rebuild branch-sensitive context on session_tree. Use `agent_settled` for completion and `ui_prompt_start/end` for waiting; `agent_end` can precede retries or follow-ups. Render native tool progress and speech state, with correct RPC/print behavior. Distinguish integrating Vox into an existing pi session (extension injection/commands) from Vox owning a new `pi --mode rpc` voice-first process; the latter has separate credential, read-scope and lifecycle obligations. Certify 0.85.1; no dependency on source-only experimental pi server/plugin APIs.

Both active lanes must share semantic operations/defaults and respect the canonical toolkit grammar while publishing their true native skill/command spellings. See [Codex](../harnesses/codex.md), [OpenCode](../harnesses/opencode.md), [pi](../harnesses/pi.md) for versioned limitations.

## Product acceptance journeys

For each harness: install in an isolated clean home, enable a test repo, choose a voice, speak a recap, change mood, operate recordings/music and observe real audible results. Use two sessions in the same repo plus a worktree and a second repo; changing one voice or stopping one call must not overwrite the others. Verify daemon-down/provider-down, remote audio host, service restart, large synthesis, interrupt during playback, disable while an event is queued, reload/resume/fork/compaction, and uninstall with another active client.

For Codex, prove hook and MCP context are the same authoritative session under subagents and concurrent tool calls; unsupported binding blocks the affected stateful feature's release. For OpenCode, observe real TUI attach/detach against a remote server and establish which component owns audio. For pi, verify no factory-time background work, stale callback delivery after /new or /tree, and finite headless exit. For voice-first features, test actual permission denial, explicit child tool/read scope and credential filtering, cancellation propagation and native steer acknowledgements; transport receipt does not promise model obedience.

Run the existing public-API, config-isolation, CLI JSON, daemon/client, conversation-state and installed CLI/MCP suites with fakes/local test daemons. Retain the injected Lux factory regression so tests never reach the operator's live display. Then perform the repository's required audible, real-entry-point demonstration for each lane; schema/unit checks are not that demonstration. [Test isolation](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/tests/test_voxd_daemon.py#L54), [public API contract](https://github.com/punt-labs/vox/blob/db1a4a9000fd1270d811e3b85f9aa67e8bcbde43/tests/test_public_api.py#L100).
