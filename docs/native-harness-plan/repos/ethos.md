## Mandatory core changes

**Make runtime context explicit throughout the service layer.** Add a validated adapter-owned context carrying harness, opaque native session, native actor/parent, canonical repository/common-dir and worktree, plus optional mission binding. Persist a mapping to the existing Ethos session ID. Keep persona identity separate from the actor ID: two instances of `bwk` must remain two participants. Extend [`internal/session/session.go:6`](https://github.com/punt-labs/ethos/blob/ace18cf46bc16ea17d27537b203a43706453cad0/internal/session/session.go#L6) without discarding existing rosters. Define start/reattach/fork/child/end/reconcile operations and durable audit ownership. Native adapters should submit trusted context out of the model's argument schema; model-supplied IDs may identify records to inspect, but cannot assert the caller or confer authorization. Preserve standalone explicit CLI/env behavior and Claude's compatibility resolver.

Extract identity, mission binding, delegation admission, result recording and cancellation orchestration into shared Go services invoked by CLI, MCP and adapters. Avoid a universal harness protocol embedded in every domain method. Complete JSON error envelopes and finite CLI entry points so OpenCode/pi can invoke the Go binary without importing private internals. MCP read and mutation methods currently share coarse tools; expose or annotate the actual read/write boundary so native policies can grant inspection without granting mission edits.

**Repair governance before promising enforcement.** [`internal/hook/pretooluse.go:23`](https://github.com/punt-labs/ethos/blob/ace18cf46bc16ea17d27537b203a43706453cad0/internal/hook/pretooluse.go#L23) emits Claude `additionalEnv`; dispatch watches the literal `Agent` tool and uses `MISSION_ID` and `ETHOS_VERIFIER_ALLOWLIST`. [`internal/hook/pretooluse_dispatch.go:55`](https://github.com/punt-labs/ethos/blob/ace18cf46bc16ea17d27537b203a43706453cad0/internal/hook/pretooluse_dispatch.go#L55) mixes Claude dispatch with mission admission. Extract normalized admission decisions and native-tool mappings, propagate bindings through an explicit launch/result contract, and test missing context as a declared condition. Canonicalize absolute paths, traversal and symlinks before write-set checks. Fix archetype-load failures that silently remove invariants. A hook guarding selected writes is not an OS sandbox; arbitrary shell writes require an enforceable native policy/sandbox or an accurately narrower claim. Unknown tools and upstream modes that bypass a hook cannot silently receive verifier status.

**Generate owned native persona assets.** [`internal/hook/generate_agents.go:62`](https://github.com/punt-labs/ethos/blob/ace18cf46bc16ea17d27537b203a43706453cad0/internal/hook/generate_agents.go#L62) targets `.claude/agents`; its generated Write/Edit shell hook and tool grants are Claude-specific. The scratch-path shortcut in generated validation also needs canonicalization. Separate semantic persona/role/mission instructions from active target renderers, retaining Claude and deferring Codex, with explicit model/tool capability mapping and no dev-plugin names. Generate only selected targets, record ownership/hashes, and keep generated runtime data out of tracked source. Reconcile static fallback agents and dynamic agents into one semantic source. Guide installation needs literal/native instruction discovery for each target; adding an `@` line to `AGENTS.md` is insufficient.

Preserve common-dir identity stores and distinct checkout audit paths. Reopen, crash and worktree deletion require reconciliation/durable sealing; a best-effort SessionEnd hook is not the sole persistence mechanism. Identity output and extension sidecars need field classification so credentials or private connector configuration do not enter persona prompts through generic context dumping.

**Provide the Biff authority registry as a separately scheduled domain capability.** Biff's M2 requirements make Ethos the system of record for public keys and scoped owner delegations: [`requirements-biffd-multihost.md:114`](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/docs/requirements-biffd-multihost.md#L114). Inspection found identity/extension stores, not an implemented secp256k1/Schnorr authority service. Add a versioned key/delegation/revocation schema and finite machine APIs for register, resolve, issue delegation, rotate/revoke and obtain verification material. Specify generation and private-key custody separately from public registry storage, with `djb` evaluating the key design and `bcs` reviewing the threat model as that requirement mandates. Agents never receive an owner's private key; owner authorization and agent authorship remain distinct. Include validity bounds, scopes, revocation sequence/time and an explicit historical-message policy. Biff owns envelope signing/verification, replay detection, forwarding and recipient policy; Ethos supplies auditable authority facts, with caching/offline/freshness failures specified. Keep Beadle's GPG stack and extensions intact. Do not convert persona/session identity into cryptographic authority implicitly or treat a raw sidecar field as a validated delegation. This is a concrete prerequisite for `BIFF-AUTH`, not a reason to block basic native persona sessions.

## Native designs

**Codex (deferred).** Publish a native plugin with its current root manifest, MCP declaration, skills and Codex hooks; render Codex agent TOML/instructions according to supported agent discovery. SessionStart/SubagentStart/Stop/SessionEnd hooks call the explicit context/admission services using actual Codex payloads. The prerequisite spike must prove authoritative session and actor propagation into tool execution and MCP calls; a hook cannot export variables into its parent, and no per-thread MCP child may be assumed. Use real Codex delegation with isolated agent roles and native permission settings. If packaged agent configuration cannot be discovered through the plugin, use supported owned registration or explicit native subtask prompts, with documented uninstall. Do not describe app-server embedding or exported shell variables as stock-plugin completion. PreToolUse/PermissionRequest adapters must use Codex's documented response semantics, never replay `additionalEnv`. Compaction rehydrates a bounded mission/persona snapshot; repeated lifecycle events are idempotent.

**OpenCode.** A native TypeScript server plugin binds tools from `sessionID`, agent and worktree context. Stateful identity/mission tools call finite JSON CLI operations with adapter-owned context, because MCP environment is process-scoped. Named native agents and the built-in delegation path carry mission lineage and explicit child policy. Enforce supported before-tool gates synchronously; do not rely on the currently unused `permission.ask` hook or event callbacks as an admission barrier. An optional TUI component can display persona/mission/roster status; it consumes the same state and is not required for CLI correctness. Verify alternative execution modes do not bypass claimed gates.

**pi coding agent.** A native TypeScript extension registers typed identity/mission tools and commands, derives context from `ctx.sessionManager`, and invokes the JSON CLI with cancellation. Track fork IDs and tree leaf positions separately; tree navigation is not a new session. Use native lifecycle events and explicit persistence, with UI status as a projection. For delegated personas, integrate the shared, explicit pi delegation supervisor: each role runs an independent supported pi process/SDK session with its own tools, prompt, lineage and cancellation. Pi has no built-in subagent tool or OS sandbox; extension trust is not mission authorization. Governance claims must match the actual allowed execution environment.

All targets share one `.punt-labs/ethos/enabled` marker. Installation, registration, repository enablement and session persona preference remain separate. Biff and Quarry integration use explicit actor/mission contracts, not global persona strings.

Run contract tests around the shared services, existing standalone session tests, and real installed-process integration; then exercise each stock harness interactively. For each target: enable outside the source checkout, select persona, create/claim a mission, launch two independent specialists, deny a forbidden write, record results, compact, reopen, fork, cancel a child, and close. Repeat with two simultaneous sessions/worktrees, a missing Biff peer, an unavailable verifier, disabled repository and uninstalled adapter. No duplicate rosters, cross-session persona changes, orphaned active claims or lost audit records are acceptable. Keep a recorded Claude zero-config, generated-agent and git-seal regression journey. Schema or headless checks alone do not certify native gating or UI behavior.
