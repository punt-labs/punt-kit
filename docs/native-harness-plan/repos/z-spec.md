## Core remediation that precedes parity claims

**Correct epistemic status first.** The open correctness epic identifies failures that would otherwise be copied onto three native surfaces. [`commands/check.py:53`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/commands/check.py#L53) verifies a file and binary, runs fuzz and persists the result; it does not reject documents containing no Z paragraphs. [`coverage.py:22`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/coverage.py#L22) recognizes the older census shape, while ProB 1.16 changes it. Distinguish absent counters from explicit zero, interrupted/incomplete exploration from passing, and “not checked/unsupported” from verified assertions. `cbc_assertions` capability is an open hypothesis requiring deliberately violating Z fixtures and real solver evidence; do not replace uncertainty with an invented support claim. Preserve supported bounded-model semantics in every display and agent summary. A bounded pass is not a theorem proof.

Reuse the existing `z-spec-st9` children, including session-spec semantic inputs and model bounds. Apply `z-spec-hhm`'s explicit product direction for `probcli` extra-argument passthrough and removal of named knobs before re-evaluating bound-specific tasks; do not introduce a competing extras allowlist or duplicate tuning layer without a new design decision. Version-gate real solver parsers and document the certified versions; the currently pinned ProB 1.15.1 is not evidence that 1.16 works. Preserve raw evidence and solver/version/options with each report.

**Complete the machine execution contract.** Add consistent JSON mode and versioned discriminants to every finite command, including doctor, enablement and failures. Retain human defaults and backwards compatibility for existing MCP consumers where needed. Convert timeout, cancellation, missing binary, invalid report and disabled repository into typed outcomes. Introduce a shared subprocess runner with cancellation, child-process cleanup, progress events, bounded logs and a clear distinction between solver timeout and transport abort. Persist results atomically with input hash and run ID; concurrent runs must not overwrite each other's results or publish stale success. Pi should call this public CLI, not parse human prose or import Python internals.

**Replace process identity with contextual session ownership.** [`server_context.py:23`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/server_context.py#L23) enforces one per-process root/gate/Lux session. [`lux/project.py:24`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/lux/project.py#L24) relies on `CLAUDE_PROJECT_DIR` to repair plugin `uv --directory` cwd changes. [`lux/identity.py:35`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/lux/identity.py#L35) derives Lux grouping from `os.getppid()` and imports a hub naming helper. These are incompatible with a shared OpenCode server and opaque Codex/pi sessions. Keep useful cached process resources, but pass validated run context to project resolution, enablement and display routing. Require canonical repository/worktree context for stateful calls; do not silently use the plugin checkout when context is missing.

Lux must expose a public structured identity contract containing native session and applet role, so z-spec no longer manufactures a private PID-shaped name. Define one adapter-owned menu subscription per logical owner; child computation should not automatically create another applet. Async display failure must remain optional for check/test/animate. Separate engine run lifetime, harness session lifetime and display subscription lifetime, including fork/reopen/disable cleanup.

**Keep repository activation native and owned.** [`commands/enablement.py:123`](https://github.com/punt-labs/z-spec/blob/a6fe3de9740459a3f2bae3889cbe0aa70a8688ba/src/punt_zspec/commands/enablement.py#L123) owns the marker, guide and Claude import. The marker is `.punt-labs/z-spec/enabled`; guide/import logic currently targets `CLAUDE.md`. Preserve atomic marker-last behavior, locking and user-authored instructions, then add selected-target guidance installation. `AGENTS.md` cannot inherit Claude's bare `@` import semantics. Installation and registration must not implicitly enable every harness.

**Complete B-Method parity and workflow seams.** Existing `b-check`/`b-animate` authored paths need `z-spec-77g`'s real deterministic CLI/MCP services. Keep authored Z/B generation, elaboration, refinement, contracts and proof workflows distinct from deterministic tool results. Large partition/audit prompts can continue authoring validated reports initially, while optional deterministic extraction proceeds under the existing exploration work. Oracle/refinement acceptance needs executable witness/counterexample/proof artifacts and independent review; do not equate a fluent model explanation with verified correspondence. Preserve the current authored command inventory and document each target's invocation mapping before renaming any workflow.

## Native adapters

**Codex (deferred).** Publish a native plugin with stdio MCP for suitable operations, authored skills and supported native instruction/agent assets. Finite tool invocation uses the existing command engine. Stateful display/enablement/report operations require the shared authoritative-context spike; no hook-to-parent env export, model-asserted current-session ID or per-thread MCP-child assumption. Lifecycle hooks register/reconcile display ownership using Codex payloads. Authoring and oracle workflows use native independent reviewers and real supported delegation. Codex tool policies distinguish reading/checking from editing sources or executing generated implementations, and missing permissions produce accurate incomplete results. Interactive Lux selection must be verified with real stock Codex; app-server embedding is a separate integration surface.

**OpenCode.** Native commands/skills express authoring workflows. A TypeScript server plugin registers typed finite CLI tools and obtains `sessionID`, agent, directory and worktree from each call. Use MCP for operations only where their scope is truly explicit and safe for a shared process; do not keep a global active Lux session. Native child agents perform independent audits with explicit tool policy and separate evidence. An optional TUI surface shows run progress and decisions, while Lux remains the rich external display through its public contract. Avoid executing a same-session prompt inside an awaited tool hook. Abort from the native session must reach the underlying solver process.

**pi coding agent.** A native TypeScript extension owns typed JSON CLI tools, commands, progress/UI and lifecycle. It obtains native session/leaf identity from pi, sends direct engine context, forwards cancellation and manages a real streaming child for long runs rather than expecting buffered `pi.exec` to become a watcher. There is no generic MCP bridge. Authored workflows use packaged skills and an explicitly declared shared pi supervisor whenever independent proof/model/code reviewers are required. Separate generated-code execution permission from read-only model inspection: pi's trusted extension mechanism is not an OS sandbox. Optional Lux integration uses direct supported transport and falls back to artifact paths/text when unavailable.

Each target must install from the release package outside any toolkit checkout, enable a target repository, generate a small real Z model, reject an empty document, type-check, animate, model-check, independently audit, and inspect a Lux report or explicit missing-Lux fallback. Run the B equivalents and an oracle fixture with a known implementation defect. Then exercise two concurrent sessions/worktrees, a spawned reviewer, compaction, resume, fork/tree navigation, cancellation during ProB, disabled repository, missing binary, native permission denial and adapter removal. Artifacts must retain solver/version/options/input identity and honest completeness; no duplicate applet, orphan process, wrong-root enablement or cross-session selection is acceptable. Reuse command/parity and installed-MCP tests, add real solver/process fixtures, and run the opt-in model workflow suite plus stock TUI/display journeys. Static prompt schema checks alone do not prove proof quality, independent delegation or live display routing.
