# Beadle: native mail clients and supervised agent workers

**Priority update — 2026-09-13:** OpenCode is P1; pi is P2. Codex designs and task rows below are deferred research, including workers and controlled voice backends. They impose no active dependency or release gate. Research/source and Beads observations remain dated 2026-09-12. See [the scope decision](../decisions.md) and the [active roadmap](../roadmap.md).

Audit baseline: `main` at `8f3f368d35457c32e0a2b021dbb43e1f36f953e2`; Go module `github.com/punt-labs/beadle`, Go 1.26.1. The full repository-scoped inventory contains 191 beads. Existing `.claude/agents/kwb.md`, `.punt-labs/vox/vox.md`, and untracked reviewer-agent edits were preserved. Findings are source review, not claims that live mail, TUI, or worker acceptance tests have passed.

Beadle has two products to integrate: interactive authenticated email access, and unattended email-triggered work. Native clients may ship before new worker backends once the shared mail/session foundations pass; enabling inbox awareness must never implicitly enable autonomous execution.

## Actual surfaces and mandatory engine work

`beadle-email` has Cobra commands for list/search/read/send/reply/move/mark/folders/contacts and administration, with global `--json`. The daemon is a separate binary. The current Go `internal` packages are implementation packages, not an externally importable SDK; `internal/channel` defines data types rather than a usable mail service interface. MCP registers 21 base tools plus two poll controls, including operations without CLI counterparts: signature verification, MIME inspection, trust checks, attachment downloads, batch operations and session identity switching. MCP currently returns formatted text; CLI list JSON drops degraded-result metadata. Native adapters need a versioned structured result/error envelope, complete finite commands, bounded output, cancellation and stable message identifiers—not parsing human output. [CLI](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/cmd/beadle-email/email_cmd.go#L145), [MCP registration](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/tools.go#L53), [text-only boundary](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/tools.go#L1479), [channel types](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/channel/channel.go#L1).

**Extract one authoritative MailService before exposing the CLI as an agent API.** The MCP `readMessage` checks sender read permission and `sendEmail` checks recipient write permission and selects encryption keys. CLI read directly fetches the message; CLI send calls `TrySendChain` without the equivalent contact write check or recipient encryption keys. The shared send transport signs according to configuration, but does not supply contact authorization. Move read redaction, trust/signature checks, all To/CC/BCC authorization, encryption selection, attachments, threading and repository metadata into service actions used by CLI, MCP and daemon. Contact permission mutations also need an explicit authority rule. Keep Beadle's GPG identity/signature design; Biff's Schnorr program is a separate protocol. Propagate `context.Context` through IMAP/SMTP/GPG/HTTP operations instead of discarding it at handlers. Decide and expose whether signing was generated versus preserved through a transport; SMTP acceptance alone cannot prove preservation (`beadle-5xog`). [MCP read gate](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/tools.go#L661), [MCP send gate](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/tools.go#L749), [CLI read/send](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/cmd/beadle-email/email_cmd.go#L403), [transport chain](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/email/chain.go#L41).

**Replace process-global identity with explicit session context.** The MCP handler's `identityOverride` explicitly assumes one process equals one session. OpenCode can share a server across sessions, and the custom WS server already shares handlers. The poller uses a separate resolver, so switching the handler's identity does not switch its watcher. Ethos roster discovery walks Claude ancestry and caches the top ancestor; global active identity and repository YAML are defaults, not per-call authorization. Introduce `(harness, native_session_id, agent_id, repo/worktree)` and authenticated account/delegation binding through the MailService, with separate subscription keys and explicit standalone CLI scope. Identity selection must not grant mailbox or contact permissions. [override](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/tools.go#L92), [switch](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/identity_tools.go#L33), [resolver](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/identity/resolve.go#L75), [roster](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/session/roster.go#L70), [poller config](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/email/poller.go#L286).

**Create a real receiver contract, independent of worker execution.** Polling compares unseen counts, suppresses the initial tick, and announces increases. Reading one message while another arrives can leave the count unchanged and miss an arrival. MCP startup unconditionally starts polling and broadcasts Claude channel notifications to every client. Implement identity/repository-scoped observation with UIDVALIDITY/UID or equivalent durable identifiers, cursor/ack, reconnect replay and deduplication; distinguish unread-count status from arrival events. Choose a documented bounded background service or supervised `beadle-email watch --jsonl` over that receiver. Do not duplicate mail polling in each harness and the execution daemon. The daemon additionally needs durable message claims and job states: current capacity-full handling skips work and repeated unread messages can be reconsidered. Recipient read/trust policy must govern notification content, not just later tool reads. [poll algorithm](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/email/poller.go#L199), [notifications/startup](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/cmd/beadle-email/admin_cmd.go#L60), [daemon admission](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/handler.go#L93).

**Describe transports accurately and repair the existing WS launch contract.** `serve` offers stdio MCP or custom newline-framed MCP over WebSocket at `/mcp`, plus `/health`; it is neither REST nor standard Streamable HTTP. Closed `beadle-nimy` added loopback binding, random-token authentication, origin checks and a read limit. However the CLI never retrieves or publishes `Token()`, while tests retrieve it directly; normal clients lack a supported credential handoff. The outbound scanner still caps responses at 64 KiB and ignores scanner errors. Repair secure token discovery/ownership, framing limits and cleanup with a real launched-process test. Standard HTTP MCP can be added if needed, but stdio is a valid initial Codex/OpenCode surface. Pi must use direct product actions, not a bridge around this custom MCP transport. [server launch](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/cmd/beadle-email/admin_cmd.go#L104), [token API](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/ws.go#L44), [scanner](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/mcp/ws.go#L199).

Repository enablement currently couples `.punt-labs/beadle/enabled` to a generated `CLAUDE.md` and an import into repository Claude guidance. Preserve one marker while separating package installation, explicit harness registration, repository awareness and session poll preference. Generate native guidance entry points without assuming Claude imports work in `AGENTS.md`. Clarify that disabling automatic awareness is different from denying a deliberate standalone email command. [enablement](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/enable/enable.go#L58).

## Native interactive integrations

The three native designs depend on MAIL, SESSION and RECEIVE below, with exact version gates from the corresponding harness reports.

| Harness | Native delivery and lifecycle | Required proof / deliberate limit |
|---|---|---|
| Codex [deferred] | Portable native plugin manifest, skills and stdio MCP backed by MailService. Native hooks bind lifecycle and perform bounded checks; authored `$inbox`/mail skills replace Claude slash/Cron instructions. Bind session context through the shared verified Codex/Ethos mechanism. | Hook code cannot change its parent's environment. Prove tool-call identity across concurrent/resumed/forked sessions before stateful tools ship. Automatic background delivery requires the native queue experiment to pass idle/busy/start/cancel/permission tests; otherwise state the supported manual-refresh behavior. No promised custom TUI badge provider. |
| OpenCode | Native npm package exporting server and optional TUI plugins. Session-aware typed tools pass `ToolContext.sessionID` to MailService; shared MCP remains only where per-call context is verified. Subscribe once per scoped receiver, use native event lifecycle, toasts/status slots, commands and SDK delivery; server `dispose` and TUI abort/onDispose release resources. | Generic plugin event callbacks are not awaited; serialize event drains and retries. `session.prompt({noReply:true})` can persist notification context; `promptAsync`/prompt needs explicit busy policy. Never await a running prompt from an awaited tool hook. Gate wake/full-content delivery on mail trust/read policy and test reconnect duplication. |
| Pi | Native TypeScript extension/package with typed tools over repaired finite CLI or direct product IPC, `registerCommand` and skills/prompt templates. Start receiver resources at `session_start`, terminate on shutdown/reload; render TUI status/widget and use `sendMessage` with a Beadle custom type and deliberate `followUp`/`steer`/`nextTurn` policy. | No generic MCP bridge or Claude process probing. Preserve external mail as attributed data, not a synthetic user instruction. Test `agent_settled`, session switch/fork/tree and generation changes, plus RPC/JSON/print paths without assuming full TUI APIs. Shell/extension transport calls still require core authorization. |

Polling frequency is a product/session preference with shared validation (`beadle-1ljl`), not a Claude CronCreate payload to translate. Compaction must not own mail cursors, trust decisions or acknowledgements. Sending, replying, moving, marking, attachments and contact changes remain explicit native tool operations subject to core and harness permissions.

## Native unattended workers

The existing `Runner` abstraction is useful, but `Spawner.Run` takes an MCP config path, a prompt-file path and Claude tool names; `Command.Runner` only permits `claude|cli`. Introduce an `AgentRunner` and semantic `WorkerSpec` containing signed recipe identity, bounded task/contract data, actor/session context, workspace, capability grants, credential grants, allowed backend/version, budgets and expected result schema. Each backend compiles native configuration and parses native events. Keep direct `CLIRunner` for signed deterministic commands. Since GPG canonicalization includes recipe execution fields, version the signed schema, preserve existing signed v1 semantics and require deliberate migration/re-signing rather than silently reinterpreting grants. [interfaces](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/pipeline.go#L46), [recipe schema](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/command.go#L59), [signature bytes](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/signature.go#L111).

Correct lifecycle defects before multiplying backends: the prompt always tells workers to run `ethos mission show`, even without shell access; result submission is omitted without Bash; the supervisor attempts mission close but logs and ignores failure. Embed the bounded contract in the task and have the supervisor validate/submit the result and finalize the mission through Ethos. Closed `beadle-vr0v` remains a regression reference, with a new residual lifecycle task justified by current source. Remove fixed `claude`/`bwk`/`mdm` mission actors, repair `ethos mcp` to the actual `serve` command (`beadle-f34m`), and preflight backend-specific service credentials instead of assuming `${VAR}` expansion. [runner](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/runner.go#L32), [prompt/registry](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/templates.go#L82), [actors/contract](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/pipeline.go#L232).

The current Claude spawner inherits real HOME, invokes `--permission-mode auto`, mixes unbounded stdout/stderr with `CombinedOutput`, and relies on prompt/tool restrictions without a complete OS boundary. Build a supervisor policy for isolated workspace/home, explicit credential mounts/env, network/filesystem/process scope, separated bounded output, process-tree cancellation, deadline and usage accounting. Preserve sender `x` permission, valid matching GPG verification or the already implemented loopback-only Trusted path, and owner-signed commands. Carry actual provenance rather than the current hardcoded trusted pipeline value. Record signed audit identity/grants/backend/config digest and execution versus reply-delivery outcome. Native worker expansion is not authority to weaken these gates. [spawner](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/spawner.go#L71), [admission](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/handler.go#L93), [pipeline](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/pipeline.go#L62).

Backend compilation must be genuinely distinct:

- **Codex (deferred):** a supervised native exec/SDK or App Server worker with a minimal task configuration and explicit sandbox/approval policy. Select one tested execution lane; an interactive plugin does not prove worker isolation. Observe structured events, terminal outcome and cancellation, validate output, then finalize the Ethos mission. Reject unsupported grants instead of broadening them.
- **OpenCode:** verify against installed 1.18.27 and researched 1.18.30. `opencode run` accepts positional/stdin task text; `-p` is password, not prompt, and `--allowedTools`/`--excludedTools` do not exist. Noninteractive run rejects permission asks, but unspecified permissions can remain permissive, so compile explicit allow/deny policy. SDK prompts accept `system`; a named agent is not required. A server worker must handle permission requests itself. Use steps plus supervisor timeout/usage/cancel; no proven native hard-dollar budget. `--pure` removes external plugins, so it cannot coexist with a design relying on an Ethos plugin gate.
- **Pi:** a supervised native SDK/RPC or JSON process with explicit extension/tool/skill discovery and grants, direct typed Punt tools, known package version, output protocol and abort handling. Pi is not an OS sandbox; the existing `beadle-tmo` containment requirement must be resolved with an actual container/process boundary before unattended release. Native multi-agent orchestration is owned by Beadle, not an assumed stock Pi feature.

The open LLMPlanner project is independent of native backend support. Do not expand autonomous planning merely to add harnesses. Existing admission/recipe tests use real GPG and Ethos but a `FakeSpawner` and `StubPlanner`; add real harmless backend executions and production mail-to-plan-to-result-to-reply coverage. [test boundary](https://github.com/punt-labs/beadle/blob/8f3f368d35457c32e0a2b021dbb43e1f36f953e2/internal/daemon/harness_test.go#L32).
