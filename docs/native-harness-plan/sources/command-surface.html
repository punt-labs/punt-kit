Punt Labs · plugin audit · change plan · 2026-08-29

Punt Labs Command Surface

The operator's rulings applied to the nine-plugin slash-command surface. Every change reads before → after with its rationale beneath. Open decisions at the bottom.

Rulings applied

  • Enablement was already specified — punt-kit/standards/tool-enable-disable.md §2.3/§2.14: the verbs are enable/disable (y|n is explicitly retired vocabulary), exposed as /<tool> enable|disable on the slash surface and action="enable"|"disable" (never a boolean) on MCP, both writing the same .punt-labs/<tool>/enabled marker. vox is the spec's own shipped reference. The audit finding is therefore a compliance gap, not a design question: lux (y|n) and z-spec (separate /enable+/disable commands) migrate; quarry's verb shape conforms; prfaq is out of scope (no per-repo presence, no marker).
  • beadle keeps /mail and /send — multi-transport intent is real; /mail is the clear email door.
  • quarry /use dies — too general; /quarry use <db> is the one door.
  • /vox:recap is correct; bare /recap in the deposited guide was too general — doc fix.
  • plan keeps its name on every door (2026-09-02): a slash-only rename does not reduce agent confusion when CLI, MCP, and library all say plan.
  • /punt:init stays. vox mute/unmute naming stays (documented UX constraint). ethos /session stays.
  • quarry /remember hint and ethos /ext get fixed.
  • biff vs beadle: help text must distinguish messaging vs email; beadle gets a /poll modeled on biff's.
  • lux dotted names are justified — the agent, not the user, builds the UIs — but the set needs a command/skill re-sort and a naming pass.
  • /help for every plugin. z-spec's breadth (Z, B, Lean) is justified; skills conversion open.
  • Window management is deprecated from the agent surface: frame.raise and anything that manipulates frame z-order, min/max state, or position goes. The human owns the window; the agent owns the content.
  • /prfaq:permissions is removed — superseded by allowed-tools frontmatter and Claude Code's modern permission flow. meeting-hive is left untouched for now — no env-var follow-through, and the auto-meeting rename is deferred with it.
  • Flat namespace: selective, criteria-gated. A bare (unprefixed) command must pass two tests, both: (1) unlikely to collide with any other tool, and (2) frequency that dictates the shorter form. The hooks deploy only each plugin's approved bare subset and clean up the rest. Applying the criteria: biff who, finger, tty, plan; vox vibe, recap, mute, unmute — 47 → 8. Notable exclusions: read/write/talk/find (generic English fails test 1), poll (biff and beadle both ship one — self-collision), all lux dotted entries (fail test 2).
  • quarry learn approved (bead b6p) as the third capture verb: remember = a specific durable fact, ingest = a URL, learn = a distilled lesson written to a lesson-tagged document and preferentially surfaced in future retrievals. Ships on CLI, MCP, and slash (/quarry:learn) — the boundary between the three verbs is derivable from the names, so the confusable-pair gate passes.

New facts found

  • /ethos:whoami is referenced in exactly one file: the workspace CLAUDE.md (2 occurrences, Ethos section). No child repo carries it.
  • punt-kit's pairs are door + engine, not duplicates. The bead-review command body is "Load and execute the bead-review skill"; auto likewise. auto's skill sets disable-model-invocation: true (the command is the only trigger); bead-review's skill is model-invocable.
  • lux's 22 dotted entries are commands, not skills, in the released plugin (0.31.1) — commands/scene.show.md etc. The released skills are scene.beads, scene.dashboard, scene.data-explorer. (The local lux checkout is a stale work branch at v0.26.0 — inspect the release cache, not the tree.)
  • The flat namespace is a shipped feature, not an accident. The 47 bare files in ~/.claude/commands/ are deployed by the production session-start hooks of biff, vox, lux, and quarry ("Deploy top-level commands if missing" — dev builds skip this, prod does it by design), and biff's plugin.json advertises the bare names as its identity ("UNIX-style team communication: /who, /finger, /plan…"). They are byte-identical to the installed plugin versions and re-deposited when missing. Removing them is therefore a product change across four shipped plugins, not a file cleanup — see open decision 4.

The standard, as settled

To be written as punt-kit/standards/slash-commands.md:

  • Namespace: pending the flat-namespace decision below.
  • Enablement: governed by the existing tool-enable-disable.md §2.3/§2.14 — slash-commands.md references it, never restates it. Self-named toggle, enable|disable vocabulary, MCP action never a boolean, both doors writing the one committed marker.
  • Help: every plugin ships /help (z-spec's is the template).
  • Polling: plugins with a polled inbox ship /poll [interval | n | status] (biff's is the template).
  • Command vs. skill: a command is a user-typed action; agent-facing knowledge and prose-triggered workflows are skills. The door + engine pattern (thin command that loads a skill) is allowed when the command must gate invocation or carry an allowed-tools grant; full duplication never is.
  • Naming: flat kebab-case for commands; dotted noun.verb names blessed for large agent-facing skill surfaces (lux). No name that shadows a Claude Code built-in with adjacent meaning, and no name whose description must disclaim a collision.
  • Window management: nothing on the agent surface manipulates frame z-order, min/max state, or position.
  • Cross-plugin vocabulary: one meaning per word org-wide; where two plugins share a metaphor (biff chat / beadle email), each command's description names the boundary.
  • Dev twins: the generated-twin + release-strip machinery (z-spec's) is the single strategy, applied to all nine.

Open decisions

z-spec workflow commands → skills? Candidates: elaborate, oracle, prove, contracts — multi-step generators the agent runs as workflows. Converting the four would take z-spec from 20 commands to 16 with no capability loss.
z-spec test → animate rename: withdraw? The CLI has test (full probcli suite) and animate (animation only) as distinct verbs, so the ratified slash rename would alias the wrong CLI verb. Proposed: keep slash test, fix the check/test opacity in descriptions. This reverses a ruling, so it needs the operator's yes.
