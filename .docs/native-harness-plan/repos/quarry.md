# Quarry: OpenCode P1 and pi P2 implementation plan

**Priority update — 2026-09-13:** OpenCode is P1; pi is P2. Codex designs and task rows below are deferred research, including workers and controlled voice backends. They impose no active dependency or release gate. Research/source and Beads observations remain dated 2026-09-12. See [the scope decision](../decisions.md) and the [active roadmap](../roadmap.md).

## Baseline and actual boundaries

Inspected clean `main`, `b0684cd66d5113773409a547a89891ad63b553ac`, `punt-quarry 3.2.1`, Python >=3.13. Repo-scoped inventory contains 392 beads. This audit read source, designs, tests and full relevant bead descriptions; it did not run live ingestion or integration tests.

Quarry already has one daemon-owned ingestion/search engine, typed HTTP contracts, a public transport client and thin MCP tools. Preserve that architecture and fix the actual session/capture seams. Historical architecture prose is not proof of current behavior: **each current daemon is fixed to one database; selected database state is in the client process, and current MCP is stdio forwarding through HTTP, not a daemon WebSocket or `/v1/mcp` endpoint.** [Database routes](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/daemon/routes/databases.py#L14), [selection singleton](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/db_pointer.py#L30), [MCP entry](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/mcp_server.py#L544).

## Mandatory product remediation

**QUARRY-CONTEXT: explicit context and target selection.** Introduce immutable normalized operation context supplied by each adapter, including harness/session/agent/repo/worktree and the authorized target. Replace implicit process-CWD lesson routing and MCP-global selected-database state. Reconcile toolkit invariant 4 against the current one-daemon-per-database topology: if selection remains a persistent session feature, its authoritative session-to-target registry belongs in a product core service, not three TS adapters; otherwise require an explicit immutable target per operation. Design this boundary before implementation rather than retrofitting a multi-database engine merely to resemble old prose. A default database and a native session's selection are different state. Legacy stdio clients may originate their own explicit context, while stateful Codex support depends on proof of authoritative native binding.

**QUARRY-SURFACE: finish the existing naming program before publishing three final schemas.** Reuse `quarry-rqoi` and `.1` through `.7`: ratify the outstanding table, then align CLI, client, MCP and HTTP. Carry the existing operator decisions on singular nouns, `document add`, noun-scoped MCP and enablement parity; the exact `db`/`database` spelling and placement of new collection search remain design decisions. Honor the bead's explicit no-alias policy in a coordinated versioned release. Collection-level ranking is new backend behavior, so do not advertise it by renaming document search; it can ship independently of current retrieval support. Add typed JSON errors and honest accepted/final-result representations. Preserve individual tool discoverability and native tool names while sharing operation intent.

**QUARRY-CAPTURE: replace format coupling with a neutral capture service.** Make adapters supply normalized message/event snapshots or a reader implementation; preserve one engine pipeline for artifact extraction, scrub policy, local shadow, naming and ingest. The current reader filters only Claude `type=user/assistant` records; pi's message entries would silently disappear, and OpenCode uses SDK message records. Do not ask new harnesses to fabricate Claude JSONL. [Reader](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/transcript_reader.py#L17).

Use a collision-resistant capture identity containing harness, full native session/agent identity, branch lineage and repo/worktree; do not use the first eight characters. Today both local filenames and daemon defaults use that truncation, and archives delete earlier matching names. Specify per-message/source IDs, snapshot revisions, idempotence, ordering, size budgets, atomic concurrent writers and resume/fork/compaction behavior. Preserve child transcript attribution already implemented by Claude SubagentStop. Bound parsing before materializing untrusted large transcripts; incorporate `quarry-9hks` role/budget fixes. [Local names](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/capture.py#L27), [daemon names](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/daemon/routes/captures.py#L109), [archive](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/transcript_reader.py#L79), [child capture](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/hooks_agent.py#L259).

Make durability and recovery precise. Existing shutdown drain/spool work protects jobs aborted after a bounded graceful shutdown and local capture artifacts provide replay; this is **not a journal of every accepted task before a process crash**. Extend the actual job lifecycle with admission journaling or a documented recoverable client/core capture spool and receipts where the new ingestion contract requires crash recovery. Keep accepted/task/indexed states distinguishable and replay deduplicated. Compaction/shutdown callbacks must not wait for embeddings. The canonical scrubbed pipeline and private permissions must remain; regex scrubbing is best effort, not a claim that arbitrary conversation capture cannot contain secrets. [Current spool guarantee](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/daemon/job_spool.py#L1).

**QUARRY-TASKS and QUARRY-ENABLE.** Add opt-in CLI wait/follow and typed terminal exit behavior under `quarry-65o5`, preserving immediate acceptance by default. An adapter may cancel its polling without pretending it canceled a committed daemon job; design any real job cancellation separately. Split the existing neutral enable/register behavior from Claude guidance projection, add explicitly selected OpenCode P1 and pi P2 registration with independently removable artifacts; defer Codex registration until reactivation. Preserve the closed marker safety work: disabled hooks stay inactive; a stale registration must be reported/reconciled rather than silently deleted. Refactor setup under `quarry-a4wt` to suggest detected harnesses and configure only the explicit selection.

Remote identity is not authorization. Preserve the existing resolver's explicit remote URL/login/loopback behavior, pinned CA, live-token reread, and rejection of nonloopback cleartext rather than implementing a naive TS fetch wrapper. Registration filesystem paths are interpreted by the daemon host; expose that in a useful selection/error flow. Keep destructive removal, captured context and remote fetches within actual authorized scope. [Target resolution](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/client/resolver.py#L38), [secure transport configuration](https://github.com/punt-labs/quarry/blob/b0684cd66d5113773409a547a89891ad63b553ac/src/quarry/client/config.py#L50).

## Native harness designs

**Codex (deferred):** native plugin with `quarry mcp` stdio configuration, native skills and command hooks. The read-only search/show lane can reuse thin MCP with an explicit immutable target; stateful selection/lessons/capture require shared context proof. Use native session/subagent/compaction events and bounded structured snapshot ingestion; never pass Codex paths to `TranscriptReader` or depend on the unstable rollout format as the sole capture contract. Validate how much conversation a stock plugin can reliably obtain. If full-history capture is unavailable, checkpoint supported turn/tool information and state that limitation explicitly; the required spike must determine a truthful native alternative before full capture parity is declared. Curated research capture is an authored native skill with user intent, not a fabricated lifecycle hook. Codex App Server hosting is a separate optional integration lane.

**OpenCode:** native server plugin and typed tools call authenticated HTTP with tool `sessionID/agent/directory/worktree`; no mutable global selection in a shared MCP process. Obtain message snapshots through the native SDK and stable event stream, checkpoint completed turns, and reconcile compacted/resumed sessions. Optional experimental pre-compaction hooks may improve fidelity but must not be the only durable capture path. Serialize asynchronous capture work and catch callback failures because event dispatch is unawaited; dispose the directory-instance receiver correctly while keeping each session's cursor independent. Optional TUI shows task/index status and offers the curated capture command. Native permission rules and actual tool authorization apply; the declared-but-unused `permission.ask` hook is not an enforcement point.

**Pi:** native TS package with `registerTool`, `registerCommand`, skills and status. Use a versioned authenticated HTTP client or finite JSON CLI requests, no generic MCP bridge. Read current branch entries through `ctx.sessionManager` and native message/compaction events, mapping them to the neutral capture contract rather than reparsing session JSONL as Claude records. Use session_start/session_shutdown for runtime replacement, session_tree for branch changes and bounded session_before_compact snapshots; generation-check late responses and abort background polling on disposal. Headless print/JSON invocation must exit without leaked timers. `pi.exec` buffers output and cannot stream request stdin; use real HTTP or an explicitly owned process when needed. Put action policy in the real operation because tool_call does not gate arbitrary extension callbacks.

Codex certification is deferred. Target OpenCode 1.18.30 with explicit 1.18.27 compatibility checks, and pi 0.85.1 with a separately evaluated 0.84.4 compatibility lane. Native capture/import contract tests must cover the actual versioned record/event formats.

## Product acceptance

In each real harness, install outside the source checkout, enable a temporary repo, register/sync a small document set, search and show a cited result, ingest a URL, remember a fact, save a scoped lesson and observe accepted then indexed status. Run curated capture and passive checkpoint workflows independently. Verify two sessions, two worktrees, two databases/targets and a child agent cannot cross-route content; use native IDs with identical eight-character prefixes to prove the collision fix.

Exercise disable while capture/polling is queued, resume/fork/tree/compaction, hard session termination, daemon unavailable/restart, accepted-job failure, oversized/malformed messages, duplicate delivery, raw source with test secret canaries, remote auth/CA rejection and denied destructive/capture actions. Assert policy denial before the side effect, no secret-bearing URL logs, and correct remote filesystem semantics. Distinguish stopping a wait from canceling daemon work. Require recovery receipts under the chosen durability guarantee instead of counting a 202 as successful indexing.

Reuse HTTP/MCP real-ASGI equivalence tests, public-client fixtures, task tests, capture/redaction tests, generated OpenAPI checks and packaged wheel round trips. Repair the existing wheel verification failure before using it as evidence. Run the explicit real-socket/hook/embedding suites where appropriate; default pytest exclusions mean a default green run is insufficient. Finally run native live sessions for lifecycle/capture plus existing Claude regression; no live database, user corpus or enabled registration is modified by this planning audit.
