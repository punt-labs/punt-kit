# Biff: OpenCode P1 and pi P2 implementation plan

**Priority update — 2026-09-13:** OpenCode is P1; pi is P2. Codex designs and task rows below are deferred research, including workers and controlled voice backends. They impose no active dependency or release gate. Research/source and Beads observations remain dated 2026-09-12. See [the scope decision](../decisions.md) and the [active roadmap](../roadmap.md).

## Baseline and actual architecture

Audited `main` at `fdf49f322a58ac04d4c55200b8f22d254889c27f`, package `punt-biff` 1.19.0, Python >=3.13. The initial worktree has edits to Claude agent definitions and `.punt-labs/vox/vox.md`; they were preserved. The repository-scoped bead inventory contains 159 items. Findings below come from source and complete relevant issue descriptions; integration tests were inspected, not run.

Biff already has a real async Python command API: exported commands return `CommandResult(text, json_data, error)`, with CLI adapters interpreting output and exits. It also has a shared `TalkState` and talk orchestration. Preserve and strengthen those boundaries instead of inventing a parallel engine. The API's `CliContext` still owns a relay/config/live session; its advertised “no I/O” means no presentation I/O, not no relay operations. [Command exports:1](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/__init__.py#L1), [result:15](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/_result.py#L15), [talk kernel:1](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/talk.py#L1).

## Required core remediation

1. **Complete biffd extraction against existing command code.** Move addressing and wall broadcasting out of `server/tools` (`biff-bvl`); replace `CliContext`-shaped service dependencies with an explicit domain session context. Move `ServerState`, relay ownership, `TalkState`, POP read semantics and state transitions into daemon services. Keep description mutation, status files, Claude display queues and host-specific formatting in the Claude adapter. Incremental migration with all existing frontend tests against daemon-backed behavior is required by R-D.8. [Inverted import:30](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/talk.py#L30), [MCP lifespan:1166](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/server/app.py#L1166).
2. **Bind session identity explicitly.** Introduce daemon attach/resume/detach/lease operations, scoped to `(harness, native_session_id, runtime_instance, agent_id, repo, worktree)` and an authenticated principal. Distinguish stable address, native thread, display tty and process lease. No global current pointer or ancestor PID becomes authority. Reconcile `biff-df0`, `biff-e04`, `biff-ecl`, `biff-qou`; preserve operator-facing named sessions while ensuring concurrent incarnations cannot steal ownership. Today `_create_mcp_server` reads Claude hints once; finite CLI creates a random tty; plan separately consults `SessionHint`. [MCP binding:1254](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/__main__.py#L1254), [plan marker:14](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/plan.py#L14).
3. **Implement M2/M3, including forwarding.** Biffd verifies signatures/nonces/timestamps, key revocation and scoped owner delegation through Ethos. It supplies an explicit delivery decision: trusted content with author/trust provenance; verified/unverified fixed wake line; failed signatures warning only. Preserve recipient policy bounds and minimum trust across forwarding chains; distinguish originator-signed from attested. Unsigned ordinary messages remain deliverable. `mesg` does not replace authenticity or authorization. Per-principal relay credentials and confidentiality (`biff-e43`, `biff-3pn`, `biff-lff`) remain real security work: signatures prevent forgery, not eavesdropping.
4. **Publish a semantic event/command contract.** `biff watch` (`biff-6vvo`) should subscribe to biffd, never reconnect to NATS independently. Include event ID, protocol version, addressed session/identity, delivery decision, provenance, count/state and reconnect cursor. Separate transport delivery acknowledgement from read-once consumption: today `read` marks messages read before returning. Define retention/replay/acknowledgment atomically without silently changing POP behavior. Add noninteractive talk operations and forward across CLI/MCP/native tools. Add stable reply references/order signals under `biff-24z` where envelope design needs them. [Read semantics:11](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/commands/read.py#L11).
5. **Uncouple setup and collaboration policy.** One repo marker remains authoritative. Install selects an explicitly requested harness; enable does not auto-enable every discovered harness. Propose amending R-OC.5's auto-detection wording accordingly. Repair `biff-kq5` with shared guide content plus native inclusion/skills, retaining the Claude guide where needed. Startup should not edit users' permissions or globally redeploy commands; current `session-start.sh` does both. Move Git/beads observers behind explicit session-aware domain events and make the plan gate query authoritative state, with separately specified recovery semantics for bookkeeping failure versus security denial. [Current startup mutations](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/plugin/hooks/session-start.sh), [enablement](https://github.com/punt-labs/biff/blob/fdf49f322a58ac04d4c55200b8f22d254889c27f/src/biff/enablement.py).

Biffd IPC authentication, owner-only endpoint/token storage, bounded requests and cancellation belong in this program. Do not expose the current single-session HTTP MCP server broadly or call it a multi-session daemon. Share Punt transport standards without requiring a particular REST interface; a local IPC client and typed JSONL projection satisfy native pi/OpenCode integration.

## Native designs and deferred Codex research

**Codex (deferred):** publish a native plugin with root manifest, MCP registration, `$biff`/workflow skills and Codex-specific command hooks. Hook handlers call daemon APIs directly using native payloads; no `CLAUDE_PLUGIN_ROOT`, ClaudeHooksEngine compatibility code, or copied shell hook parser. Stateful tools depend on the punt-kit/Ethos Codex per-call context spike. Preferred receive path is a Biff-owned authenticated subscription/queue worker targeting exact registered Codex thread IDs. `codex queue` is a native candidate, but its typed queue APIs are experimental and enqueue/start/ack behavior is not proven: `biff-lp5r` must retain a real interactive acceptance gate. Do not claim idle receive as complete until it passes. No verified arbitrary native badge provider exists; use actual tool/message output and documented delivery status.

**OpenCode:** publish one npm adapter with native `./server` and optional `./tui` entrypoints. Native tools call biffd with `context.sessionID` and explicit repo context; existing generic MCP may remain for proven context-free/read operations, but one shared MCP process must not choose the active identity. Subscribe once per appropriate server scope, route to sessions, expose keyed TUI unread/presence and direct controls. Use standard SDK prompt/noReply and native `chat.message` where appropriate; experimental history transforms are optional. SP-1/SP-2/SP-4 source evidence now exists, but live busy/final-loop races, noReply persistence and cleanup remain release gates. No polling on relay→daemon→OpenCode path. Named event callbacks run unawaited in the host: own serialization and catch errors. Never await a full session prompt inside an awaited hook. Biffd supplies trusted content versus wake-line decisions; plugin merely delivers them.

**pi:** publish `@punt-labs/biff-pi` using native extension tools/commands, keyed status and `sendMessage` with typed external content. Use biffd's direct client or repaired finite CLI/watch with an explicit attached session. No MCP bridge; no unread-file scraping; no process-tree identity resolution. Open resources on `session_start`, stop on `session_shutdown`; distinguish `agent_settled`, reload/fork/tree navigation and stale generations. The daemon's decision controls whether to show, queue or wake; pi `triggerTurn` is the delivery mechanism, not a grant. Do not silently replace the program's trusted-injection default with an adapter's stricter universal next-turn default. Preserve user controls, limits and signed policy in the core.

Harness versions/contracts and upstream source are detailed in [Codex](../harnesses/codex.md), [OpenCode](../harnesses/opencode.md), [pi](../harnesses/pi.md).

## Product acceptance journeys

In each harness, enable one repo, attach the user/agent identities, set a plan, exchange signed write/forward/talk with a second harness, distinguish each trust class, read once, reply with provenance and stop receiving with `mesg`. Codex must demonstrate exact-thread queue wake in stock interactive runtime; OpenCode must demonstrate real TUI badges plus event-only push; pi must demonstrate direct native tools and typed external messages without MCP.

Repeat with two sessions in one repo, two worktrees, companion identity, nested workers, resume/fork/compaction/cancel, stale peer, daemon restart, duplicate/reordered events and crash between host delivery and acknowledgement. No reply or read consumes another identity's inbox. Policy denial is identical through CLI/MCP/direct native tools, and a forged claimed session ID cannot acquire authority. Disable/uninstall one adapter stops only its leases/subscriptions and leaves other harnesses working. Published package tests must run outside source checkout without Claude installed; preserve separate existing Claude regression tests and hosted/local NATS tiers. Schema/unit success does not prove live wake, TUI or remote transport behavior.
